สัดส่วนคะแนน 5 ส่วนหลัก (Total 40%)

1. Idea + Pain-point + Ref 10%
  • Pain point: ปัญหาคืออะไร
  • User: กลุ่มเป้าหมายคือใคร
  • Idea / Solution: ทำอะไร (What), ทำทำไม (Why), ทำไมต้องใช้ NLP, ดีกว่าเดิมอย่างไร
  • Methodology: วิธีการทำ Data, Model, ขอบเขต (Limitation)
  • Reference: แหล่งอ้างอิงงานวิจัย / Repo
2. Product & Results 10%
  • Real Product (5%): Deploy ขึ้นใช้งานได้จริง (Website / Webapp / Bot) มี Link ใช้งานได้จริง
  • Results (5%): มี Train-Test data, มี Metrics ประเมินผล, ต้องมีโมเดลเทียบกับ Baseline, ทำ Error analysis
3. Code & GitHub 5%
  • GitHub Repo: ลิงก์โค้ดชัดเจน ทุกคนในทีมต้องมี Commit
  • README.md: อธิบาย Idea, How to use / run / customize, ข้อมูล Data + Results, และรายชื่อสมาชิก + บทบาท
4. Presentation + Q&A 10%
  • Presentation (5%): วิดีโอสาธิตผลิตภัณฑ์ (Demo video) + นำเสนอหน้าห้อง (Pitching & Live demo)
  • Q&A (5%): ถามกลุ่มอื่นได้ (+1 คะแนน/คำถาม เดี่ยว), ตอบคำถามกลุ่มตนเองได้ (+1 คะแนน กลุ่ม)
5. Teamwork (รายบุคคล) 5%
  • Git commit count (2%): ตรวจประวัติการทำงานจริงจาก Git commit
  • MS Form (3%): แบบฟอร์มประเมินการทำงานร่วมกันและการมีส่วนร่วมในทีม
Rules & Critical Conditions

กติกาสำคัญ & เช็กลิสต์สิ่งที่ต้องส่ง

กติกาเรื่อง Bug ใน Product:
• หาก Product ของกลุ่มพบ Bug: หัก -0.5 คะแนน / error
• หากทดสอบและ พบ Bug ของกลุ่มอื่น: ได้คะแนนพิเศษ +0.5 คะแนน / error
• กรณีไม่มี Product (No Product): ได้สูงสุดเพียง 2% และต้องอธิบายเหตุผลชัดเจนว่าทำไมถึงไม่สำเร็จ (Why it failed) พร้อมแสดง Mock product (Expected results)
กลยุทธ์การเก็บคะแนน Q&A (5%): แต่ละกลุ่มถามได้สูงสุด 5 คำถาม โดยการตั้งคำถามถามกลุ่มอื่นจะเพิ่มคะแนนเดี่ยว (+1 ต่อข้อ) และการตอบคำถามของกลุ่มตนเองได้ถูกต้องจะเพิ่มคะแนนกลุ่ม (+1)

Team Allocation Guide

แนวทางการแบ่งบทบาททีม 6 – 7 คน

เพื่อให้ทุกคนมี Git commit และบทบาทที่ชัดเจนใน README.md ตามเกณฑ์คะแนน Teamwork (5%) แนะนำให้จัดสรรหน้าที่ดังนี้:

1–2. Data Engineer & Baseline Analyst: รวบรวม Dataset, ทำ Data Preprocessing/Cleaning, สร้างและรันโมเดล Baseline เพื่อเก็บตัวเลขเปรียบเทียบ
3–4. NLP & Model Specialist: Fine-tune โมเดลหลัก (Transformer/LLM), คำนวณ Metrics (Accuracy/F1/ROUGE), ทำ Error Analysis
5–6. Full-Stack / Deployment Engineer: พัฒนา UI/UX (Streamlit / Gradio / Web App / LINE Bot), เชื่อมต่อ API และ Deploy ขึ้น Cloud เพื่อไม่ให้เกิด Bug
7. Product Lead, Pitching & QA: จัดทำสไลด์ Pitching, อัดคลิป Video Demo, ดูแล README.md และทดสอบหา Bug ภายในรวมถึงเตรียมคำถาม Q&A

เปรียบเทียบ 6 ตัวเลือกหัวข้อ

6 แนวทางสำหรับ mini project วิชา Natural Language Processing แต่ละแนวทางมีบรรทัดฐาน (dataset, baseline, หรืองานที่ deploy จริง) รองรับอยู่แล้ว จึงเปรียบเทียบผลงานของทีมกับของจริงได้ และมีตัวอย่างที่คนอื่นทำสำเร็จมาก่อนให้อ้างอิง

เกณฑ์ที่ใช้คัดตัวเลือกเหล่านี้: มี dataset หรือ baseline สาธารณะให้เทียบผลได้ทันที, มีงานวิจัยหรือ repo ที่ทำสำเร็จมาก่อนจริงให้อ้างอิง, และ deploy เป็นโปรดักต์ใช้งานได้จริงภายในเวลาของโปรเจคระยะสั้น

Sentiment / Text Classification

1. วิเคราะห์อารมณ์ข้อความภาษาไทย

การจำแนกข้อความ ความยาก: ต่ำ–ปานกลาง สัปดาห์ 4–5 (embeddings / language model)

คืออะไร

ระบบจำแนกอารมณ์หรือหมวดหมู่ของข้อความภาษาไทยจากโซเชียลมีเดีย โดย fine-tune โมเดลภาษา WangchanBERTa บนชุดข้อมูล Wisesight Sentiment Corpus แล้ววัดผลเทียบกับ baseline ที่ทีม PyThaiNLP เผยแพร่ไว้แล้ว (fastText, Linear SVM, ULMFit) ทำให้ทีมมีตัวเลขที่ต้องเอาชนะอยู่แล้วตั้งแต่วันแรก

อินพุตและเอาต์พุต

Input อินพุต

ข้อความภาษาไทย (โพสต์ คอมเมนต์ รีวิว) เป็นข้อความเดี่ยวหรือไฟล์ CSV จำนวนมาก

Output เอาต์พุต

ป้ายอารมณ์ (positive / neutral / negative / question) พร้อมค่าความมั่นใจของแต่ละข้อความ

ปัญหาที่แก้ไข

แบรนด์และธุรกิจได้รับคอมเมนต์จำนวนมากทุกวันแต่ไม่มีเวลาไล่อ่านทั้งหมดเพื่อประเมินความพอใจของลูกค้า ทำให้พลาดสัญญาณเชิงลบที่ควรรีบแก้ไข

ต่อยอดไปสู่ระบบอะไรได้บ้าง

  • Social Listening Dashboard — แดชบอร์ดติดตามความรู้สึกลูกค้าต่อแบรนด์แบบเรียลไทม์
  • ระบบแจ้งเตือนวิกฤต — ส่งแจ้งเตือนอัตโนมัติเมื่อพบข้อความเชิงลบจำนวนมากในเวลาสั้น
  • Customer Feedback Monitoring — เชื่อมกับ LINE OA หรือ Facebook Page ขององค์กรเพื่อคัดกรองข้อความที่ต้องตอบกลับก่อน

เอกสารอ้างอิงและตัวอย่างที่มีอยู่แล้ว

PyThaiNLP — Thai Text Classification Benchmarks github.com/PyThaiNLP

Baseline พร้อมใช้บน 4 dataset ด้วย fastText, linear model และ ULMFit — ใช้เป็นเส้นเทียบผลได้ทันที
Wisesight Sentiment Corpus github.com/PyThaiNLP

ชุดข้อมูลข้อความโซเชียลไทย 26,737 ข้อความ พร้อมป้ายอารมณ์ 4 คลาส

โมเดลภาษาไทยจาก VISTEC-depa ที่ finetune บน Wisesight ไว้แล้ว ใช้เป็นจุดเริ่มต้นในการปรับต่อ

Fake News Detection

2. ตรวจสอบข่าวปลอมภาษาไทย

การจำแนกข้อความ + IR ความยาก: ปานกลาง มีงานวิจัยรองรับหนาแน่น

คืออะไร

ระบบให้คะแนนความน่าเชื่อถือของข่าวหรือข้อความภาษาไทย โดยอ้างอิงแนวทางจากงานวิจัยที่ตีพิมพ์แล้ว ซึ่งผสาน information retrieval (ดึงข่าวจากเว็บ) เข้ากับ NLP สำหรับสกัด feature และ machine learning classifier สำหรับตัดสินผล

อินพุตและเอาต์พุต

Input อินพุต

ลิงก์ข่าว หรือข้อความ/พาดหัวข่าวที่ต้องการตรวจสอบ

Output เอาต์พุต

คะแนนความน่าเชื่อถือ พร้อมเหตุผลประกอบ เช่น การใช้ภาษาเร้าอารมณ์ หรือความสอดคล้องกับข่าวจากแหล่งอื่น

ปัญหาที่แก้ไข

ข้อมูลผิดและข่าวปลอมแพร่กระจายเร็วกว่าการตรวจสอบด้วยคน โดยเฉพาะช่วงวิกฤตหรือข่าวการเมือง ผู้ใช้ทั่วไปไม่มีเครื่องมือตรวจสอบเบื้องต้นก่อนแชร์ต่อ

ต่อยอดไปสู่ระบบอะไรได้บ้าง

  • Browser Extension — ตรวจข่าวปลอมแบบเรียลไทม์ขณะเลื่อนดูฟีดข่าว
  • LINE / Messenger Bot — ตรวจสอบลิงก์ก่อนแชร์ในกลุ่มแชท
  • ระบบ Fact-checking ภายในองค์กรสื่อ — คัดกรองข่าวก่อนเผยแพร่หรือเผยแพร่ซ้ำ

เอกสารอ้างอิงและตัวอย่างที่มีอยู่แล้ว

Thai Fake News Detection Based on IR, NLP and ML SN Computer Science, 2021

งานวิจัยเสนอ framework 3 ส่วน (IR / NLP / ML) เก็บข้อมูลจากเว็บข่าวไทยจริง
Ensemble ML for Identifying Fake News Headlines in Thailand ECTI Transactions (TCI), 2024

เปรียบเทียบโมเดล ensemble หลายแบบสำหรับตรวจพาดหัวข่าวปลอมไทยโดยเฉพาะ
The COVID-19 Fake News Detection in Thai Social Texts Bulletin of EEI

ใช้ transfer learning (BERT, ULMFiT, GPT) ร่วมกับการแปลข้อมูลจากอังกฤษเป็นไทยเพื่อขยาย dataset

3. สรุปข่าวไทยอัตโนมัติ

Extractive + Abstractive ความยาก: ปานกลาง สัปดาห์ 6 (encoder–decoder / attention)

คืออะไร

ระบบสรุปข่าวภาษาไทยแบบสองขั้นตอน ใช้ TextRank คัดประโยคสำคัญออกมาก่อน แล้วส่งให้ mBART ที่ finetune แล้วสร้างข้อสรุปแบบ abstractive ประเมินผลด้วย ROUGE และ BERTScore เทียบกับ baseline อย่าง Lead-3

อินพุตและเอาต์พุต

Input อินพุต

URL ข่าว หรือเนื้อข่าวฉบับเต็มที่วางเข้าไปตรง ๆ

Output เอาต์พุต

ข้อความสั้น 2–4 บรรทัดที่คงประเด็นหลักไว้ พร้อมคะแนนเทียบ baseline

ปัญหาที่แก้ไข

ข่าวออนไลน์ยาวและมีจำนวนมาก ผู้อ่านไม่มีเวลาไล่อ่านทั้งหมดแต่ต้องการรู้ประเด็นหลักอย่างรวดเร็ว

ต่อยอดไปสู่ระบบอะไรได้บ้าง

  • Browser Extension สรุปข่าว — สรุปบทความให้อัตโนมัติขณะเปิดอ่าน
  • ระบบสรุปเอกสารในองค์กร — สรุปรายงานประชุมหรือเอกสารราชการภาษาไทยที่ยาว
  • ฟีเจอร์ในแอปข่าวหรือ RSS Reader — แสดงสรุปก่อนให้ผู้ใช้เลือกอ่านฉบับเต็ม

Spelling & Grammar Correction

4. ตรวจคำผิดและไวยากรณ์ภาษาไทย

Sequence Labeling / Seq2Seq ความยาก: ปานกลาง สัปดาห์ 6–7 (seq2seq / Transformer)

คืออะไร

ระบบตรวจและแก้คำผิดหรือไวยากรณ์ภาษาไทย โดยต่อยอดจาก baseline ที่ใช้ Conditional Random Field (CRF) ของ PyThaiNLP ไปเป็นโมเดล neural หรือ Transformer ตามแนวทางงานวิจัยที่ตีพิมพ์แล้ว

อินพุตและเอาต์พุต

Input อินพุต

ข้อความภาษาไทยที่อาจมีคำสะกดผิดหรือไวยากรณ์ไม่ถูกต้อง

Output เอาต์พุต

ปัญหาที่แก้ไข

การพิมพ์ผิดหรือสะกดผิดพบบ่อยในแชท อีเมลธุรกิจ และเอกสารราชการ ทำให้สื่อสารดูไม่เป็นมืออาชีพหรือเข้าใจผิดพลาด

ต่อยอดไปสู่ระบบอะไรได้บ้าง

  • ปลั๊กอินสำหรับ Word / Google Docs — ตรวจคำผิดภาษาไทยขณะพิมพ์เอกสาร
  • Auto-correct บนคีย์บอร์ดมือถือ — แก้คำผิดแบบเรียลไทม์ขณะพิมพ์แชท
  • ระบบ QA เอกสารราชการ — ตรวจสอบความถูกต้องก่อนเผยแพร่เอกสารทางการ

RAG Chatbot / Document QA

5. แชทบอทตอบคำถามจากเอกสาร

Retrieval-Augmented Generation ความยาก: ปานกลาง สัปดาห์ 8–10 (LLM / Multimodal)

คืออะไร

แชทบอทตอบคำถามจากเอกสารภาษาไทยด้วยเทคนิค Retrieval-Augmented Generation (RAG) ระบบจะค้นข้อมูลที่เกี่ยวข้องจาก vector database ก่อน แล้วส่งให้ Thai LLM สร้างคำตอบโดยอ้างอิงเนื้อหาจากเอกสารจริง ไม่ใช่ตอบจากความจำของโมเดลล้วน ๆ

อินพุตและเอาต์พุต

Input อินพุต

คำถามภาษาไทย ร่วมกับคลังเอกสาร (PDF คู่มือ ระเบียบ หรือสรุปวิชา) ที่อัปโหลดไว้ล่วงหน้า

Output เอาต์พุต

คำตอบภาษาไทยพร้อมอ้างอิงตำแหน่งในเอกสารต้นทางที่ใช้ตอบ

ปัญหาที่แก้ไข

ผู้ใช้ต้องเสียเวลาไล่หาข้อมูลในเอกสารยาว ๆ ทุกครั้งที่มีคำถาม เช่น คู่มือการใช้งาน ระเบียบข้อบังคับ หรือสรุปเนื้อหาวิชา

ต่อยอดไปสู่ระบบอะไรได้บ้าง

  • Internal Knowledge Assistant — ผู้ช่วยตอบคำถาม HR หรือ IT Helpdesk ภายในองค์กร
  • Chatbot ตอบคำถามนักเรียน/นักศึกษา — จากเอกสารการเรียนหรือคู่มือของมหาวิทยาลัย
  • ระบบให้คำปรึกษาเบื้องต้น — ตอบคำถามจากเอกสารกฎหมายหรือสัญญาจริงขององค์กร

เอกสารอ้างอิงและตัวอย่างที่มีอยู่แล้ว

Domain-specific Word Segmentation / NER

6. ตัดคำและหา Entity เฉพาะโดเมน

Word Segmentation / Sequence Labeling ความยาก: ปานกลาง–สูง สัปดาห์ 2 (word segmentation / POS)

คืออะไร

โมเดลตัดคำและหา named entity ภาษาไทยที่ปรับให้เหมาะกับโดเมนเฉพาะทาง เช่น การแพทย์หรือกฎหมาย โดยเทียบผลกับ baseline ทั่วไปที่มีอยู่แล้ว เช่น DeepCut และ SynThai ซึ่งวัด F-measure ไว้ชัดเจน

อินพุตและเอาต์พุต

Input อินพุต

ข้อความภาษาไทยในโดเมนเฉพาะ เช่น ใบสั่งยา หรือข้อสัญญา

Output เอาต์พุต

ข้อความที่ตัดคำแล้ว พร้อม tag entity ที่พบ เช่น ชื่อยา มาตรากฎหมาย หรือชื่อบุคคล

ปัญหาที่แก้ไข

โมเดลตัดคำทั่วไปมักพลาดคำศัพท์เฉพาะทางที่ไม่อยู่ในคลังคำปกติ ทำให้ระบบปลายทางอย่างการค้นหาหรือแชทบอททำงานผิดพลาด

ต่อยอดไปสู่ระบบอะไรได้บ้าง

  • ระบบค้นหาเอกสารเฉพาะทาง — ค้นหาเอกสารการแพทย์หรือกฎหมายได้แม่นยำขึ้น
  • Document Automation — สกัดข้อมูลจากใบสั่งยาหรือสัญญาแบบอัตโนมัติ
  • ฐานข้อมูล Entity สำหรับ Chatbot เฉพาะทาง — ใช้เป็นชั้นเข้าใจภาษาให้แชทบอทในโดเมนนั้น

เอกสารอ้างอิงและตัวอย่างที่มีอยู่แล้ว
